# F.CSA313-lab5

## Даалгавар 2: Тест дизайн

### Алхам 1. Бие даан тестлэгдэх функц

**Хичээлд бүртгүүлэх** — `POST /registrations`, body: `{"studentID": ..., "courseID": ...}`.

- Интерфейсийн төрөл: procedural interface (REST API).
- Энэ нь системийн "үйл үг" буюу интерфейсийн санал болгодог өндөр түвшний чадамж. Тусад нь тестэлж болох, сайн тодорхойлогдсон функц.
- `PUT /students/:id`, `PUT /courses/:id` нь тестлэгдэх функц **биш**. Эдгээр нь зөвхөн setup (initialization) хийнэ.

Хариуны семантик (Лекц 5): `201` = амжилттай, `200 + ERROR_*` = оролтод суурилсан алдаа, `400` = хүсэлтийн формат буруу.

### Алхам 2. Сонголтууд

Сонголт нь зөвхөн POST-ийн параметр биш. Setup-аар (өгөгдлийн санд) хянаж болох далд оролтууд ч орно.

| № | Сонголт | Төрөл | Тайлбар |
|---|---|---|---|
| 1 | Оюутны ID-гийн хүчинтэй байдал | Параметр `studentID` + орчин (санд байгаа эсэх, статус) | PUT /students-аар хянана |
| 2 | Оюутны өмнө үзсэн хичээлүүд | Орчин (setup) | `coursesTaken` |
| 3 | Хичээлийн ID-гийн хүчинтэй байдал | Параметр `courseID` + орчин | PUT /courses-аар хянана |
| 4 | Хичээлийн урьдач нөхцөлүүд | Орчин (setup) | `prerequisites` |

### Алхам 3. Төлөөлөх утгууд

Лекцийн эквивалент ангиудаар хуваасан. Анги бүрээс нэг утга авна.

| Сонголт | Төлөөлөх утга (анги) | Бодит утгын жишээ |
|---|---|---|
| 1. Оюутны ID | Идэвхтэй оюутан | `status:"active"` |
| | Идэвхгүй оюутан | `status:"inactive"` |
| | Байхгүй оюутан | PUT хийгээгүй ID |
| 2. Үзсэн хичээлүүд | Урьдач нөхцөл хангана | `coursesTaken:["CS201","CS250"]` |
| | Хангахгүй | `coursesTaken:[]` эсвэл дутуу |
| 3. Хичээлийн ID | Байгаа хичээл | PUT хийсэн код |
| | Байхгүй хичээл | PUT хийгээгүй код |
| 4. Урьдач нөхцөл | Бүгд үзсэн | урьдач `[CS201]`, үзсэн `[CS201]` |
| | Огт үзээгүй | урьдач `[CS201]`, үзсэн `[]` |
| | Зарим нь үзсэн | урьдач `[CS201,CS202]`, үзсэн `[CS201]` |
| | (хязгаар) Урьдачгүй | `prerequisites:[]` |

Нийт хослол: 3 × 2 × 2 × 3 = **36**. Боломжгүй хослолуудыг хасна:

- Байхгүй оюутанд "урьдач нөхцөл хангах эсэх" сонголт утгагүй.
- Байхгүй хичээлд "урьдач нөхцөл" сонголт утгагүй.

Бүх хослолыг бичихгүй. Лекцийн **each choice coverage** стратегиар анги бүрийг дор хаяж нэг удаа ажиллуулна.

### Алхам 4. Спецификаци (тест кейсийн "жор")

Стратеги: happy path 1 + алдааны анги бүрд 1 (4) + давхар алдаа 2 + хязгаарын тохиолдол 3 = **10 спецификаци**.

| № | Төрөл | Оюутан | Үзсэн хичээл | Хичээл | Урьдач нөхцөл | Хүлээгдэх статус | Хүлээгдэх result |
|---|---|---|---|---|---|---|---|
| S1 | Happy path | Идэвхтэй | Хангана | Байгаа | Бүгд үзсэн | 201 | `OK` |
| S2 | Алдаа: идэвхгүй оюутан | Идэвхгүй | Хангана | Байгаа | Бүгд үзсэн | 200 | `ERROR_INACTIVE_STUDENT` |
| S3 | Алдаа: байхгүй оюутан | Байхгүй | — | Байгаа | — | 200 | `ERROR_NO_STUDENT` |
| S4 | Алдаа: байхгүй хичээл | Идэвхтэй | — | Байхгүй | — | 200 | `ERROR_NO_COURSE` |
| S5 | Алдаа: урьдач хангаагүй | Идэвхтэй | Хангахгүй | Байгаа | Огт үзээгүй | 200 | `ERROR_PREREQUISITES` |
| S6 | Давхар алдаа: идэвхгүй + урьдач дутуу | Идэвхгүй | Хангахгүй | Байгаа | Огт үзээгүй | 200 | таамаглал: `ERROR_INACTIVE_STUDENT` (тестээр баталгаажуулна) |
| S7 | Давхар алдаа: байхгүй оюутан + байхгүй хичээл | Байхгүй | — | Байхгүй | — | 200 | таамаглал: `ERROR_NO_STUDENT` (тестээр баталгаажуулна) |
| S8 | Хязгаар: зарим урьдач хангасан | Идэвхтэй | Хангахгүй | Байгаа | Зарим нь үзсэн | 200 | `ERROR_PREREQUISITES` |
| S9 | Хязгаар: урьдачгүй хичээл + хоосон `coursesTaken` | Идэвхтэй | `[]` | Байгаа | Урьдачгүй `[]` | 201 | `OK` |
| S10 | Хязгаар: талбар дутуу (`courseID` байхгүй) | — | — | — | — | 400 | `ERROR_BAD_REQUEST` |

> S6, S7: заавар нэг хүсэлтэд хэд хэдэн алдаа байвал аль нь буцахыг заагаагүй. Postman-аар бодитоор ажиллуулж ажигласан үр дүнг доорх "Давхар алдааны ажиглалт" хэсэгт бичнэ.

#### Давхар алдааны ажиглалт

| Спец | Таамаглал | Бодит ажиглалт (Postman) |
|---|---|---|
| S6 | `ERROR_INACTIVE_STUDENT` | _тест ажиллуулсны дараа бөглөнө_ |
| S7 | `ERROR_NO_STUDENT` | _тест ажиллуулсны дараа бөглөнө_ |

Дүгнэлт: _(ж: сервер оюутны шалгалтыг хичээлийнхээс түрүүлж хийдэг гэж тестээр тогтоосон)_
